# RoboBASIC 1.0 - Robot Programming Language
## KaivosAI Automation Language

### About RoboBASIC
**RoboBASIC** is a simple, label-based programming language designed for autonomous robot control in the KaivosAI mining simulation. The name combines "Robo" (robots) with "BASIC" to emphasize its simple, BASIC-inspired syntax that's easy to learn and use.

### Design Philosophy
- Simple, label-based scripting
- Autonomous material transfer between mines, storage, and bases
- Conditional execution, control flow, and inter-robot messaging
- No line numbers - uses readable labels for jumps
- Inspired by BASIC, Assembly, and modern scripting languages
- Commands are non blocking. Except: wait
- No variables
- No loops

## Command Reference

### Comments

**; comment text**
- Lines starting with `;` are comments (ignored by parser)
- Comments can also appear at end of line after command
- Everything after `;` is ignored
- Example: `; This is a comment`
- Example: `GOTO :mine ; Move to mine`
- Example: `:LOOP ; Load materials`


### Label Declaration

**:LABEL**
- Declares a jump target with name LABEL
- Must be at start of line, followed by colon
- Label names: uppercase letters and numbers
- Example: `:LOOP` or `:START` or `:MINE5`
- Labels cannot be on same line as command




### Movement Commands

**SET TARGET X Y**
- Sets robot target to coordinates X Y and finds path to target
- Target is stored with robot (robot.target)
- Example: `SET TARGET 13 1`

**SET TARGET #ID**
- Sets robot target to object ID location and finds path to target
- Example: `SET TARGET #5`

**MOVE**
- Attempts to move robot one step along current path toward target
- If robot has target set and path exists: move one step, remain in MOVING state, continue program
- If robot is already at target: remain in TARGET state (no movement), continue program
- If robot has no target set: ERROR(no target set), program halts
- If target is unreachable (no valid path): robot enters BLOCKED state, continue program
- Returns same movement each tick until target reached or path blocked
- Note: MOVE executes pathfinding created by SET TARGET command. Use directional commands (UP/DOWN/LEFT/RIGHT) for manual movement

**UP [N]**
**DOWN [N]**
**LEFT [N]**
**RIGHT [N]**
- Non-blocking commands that calculate and set a new TARGET from robot's current position
- Calculate N tiles in specified direction from robot's current position
- If N is omitted, calculate one tile in the direction
- Example: `UP 3` calculates target 3 tiles above robot's current position
- Example: `LEFT` calculates target 1 tile to the left of robot
- Note: These commands execute once and immediately continue to next command (non-blocking)

### Material Loading/Unloading

**LOAD [N]**
- Initiates material loading operation
- With N: load exactly N amount of material (1 material unit per game tick)
- Without N: load until robot is full OR source (adjacent mine/storage/base) is empty
- Always loads from adjacent tile (directly next to robot)
- Never loads from other robots or empty locations
- Transfer rate: exactly 1 material unit per game tick (external to command)
- Continues until condition met (use IF LOADING to check status)
- If no adjacent object with material: operation fails silently, robot not in LOADING state
- Example: `LOAD` or `LOAD 4`

**UNLOAD [N]**
- Initiates material unloading operation
- With N: unload exactly N amount of material (1 material unit per game tick)
- Without N: unload until robot is empty OR destination (adjacent storage/base) is full
- Always unloads to adjacent tile (directly next to robot)
- Never unloads to other robots or mines
- Transfer rate: exactly 1 material unit per game tick (external to command)
- Continues until condition met (use IF UNLOADING to check status)
- If no adjacent storage/base location: operation fails silently, robot not in UNLOADING state
- Example: `UNLOAD` or `UNLOAD 4`

### Control Flow Commands

**GOTO :LABEL**
- Jump to line starting with :LABEL
- This doesn't change target of robot.
- Example: `GOTO :start`

**IF [NOT] AT TARGET GOTO :LABEL**
- If robot position equals target position, jump to label
- Use NOT to jump if NOT at target
- Example: `IF AT TARGET GOTO :unload`

**IF [NOT] HAVE TARGET GOTO :LABEL**
- If robot has target set, jump to label
- Use NOT to jump if NO target is set
- Example: `IF NOT HAVE TARGET GOTO :error`

**IF [NOT] LOADING GOTO :LABEL**
- If robot is loading material, jump to label
- Use NOT to jump if NOT loading
- Example: `IF LOADING GOTO :wait`

**IF [NOT] UNLOADING GOTO :LABEL**
- If robot is unloading material, jump to label
- Use NOT to jump if NOT unloading
- Example: `IF UNLOADING GOTO :wait`

**IF [NOT] FULL GOTO :LABEL**
- If robot inventory is full, jump to label
- Use NOT to jump if NOT full
- Example: `IF FULL GOTO :unload`
- Example: `IF NOT FULL GOTO :load`

**IF [NOT] EMPTY GOTO :LABEL**
- If robot inventory is empty, jump to label
- Use NOT to jump if NOT empty
- Example: `IF EMPTY GOTO :load`
- Example: `IF NOT EMPTY GOTO :unload`

**WAIT N**
- Pause program execution for N game ticks (N must be positive integer)
- Robot state remains unchanged while waiting
- Execution costs 1 tick to start WAIT + N ticks waiting = N+1 ticks total
- After N waiting ticks, execution continues to next command on tick N+1
- Example: `WAIT 10` starts on current tick and continues on tick 10 ticks later

**END**
- Stop program execution immediately
- Robot becomes idle

**NOP** (No Operation)
- Empty command or blank line that does nothing
- Blank line (no label, no command) is treated as NOP
- Explicit `NOP` keyword is NOT supported (not in command set)
- Used for spacing, placeholders, or readability
- Does not affect program flow
- Consumes no game tick (free operation, execution pointer increments but no tick used)

**ERROR(TEXT)**
- Display error message and stop program execution
- Example: `ERROR(Robot malfunction detected)`

**PRINT(TEXT)**
- Print text to Events log
- Example: `PRINT(Loading complete)`


## Implementation Notes

### Robot State Machine

Robot can have the following execution modes (robot.execution_mode):
- **RUN**: Robot program is executed. When entering RUN mode, robot state is set to IDLE.
- **STOP**: Robot program is not executed
- **ERROR**: Robot has stopped due to error

While in RUN execution mode, robot can have the following STATE (robot.state):
- **IDLE**: No target set, not loading/unloading
- **MOVING**: Robot has target set and pathfinding route exists
- **BLOCKED**: Robot has target set but cannot move (path blocked or invalid)
- **LOADING**: Currently transferring material from adjacent location
- **UNLOADING**: Currently transferring material to adjacent location
- **TARGET**: Robot's position equals target position (goal reached)



### Execution Model
- Programs execute one command per game tick
- Labels are resolved at parse time (before execution begins)
- SET TARGET, UP/DOWN/LEFT/RIGHT, LOAD, UNLOAD commands are non-blocking:
  - Execute once, set/initiate their action, then continue to next command
  - LOAD/UNLOAD continue running in background until complete (check with IF LOADING/UNLOADING)
  - UP/DOWN/LEFT/RIGHT calculate new target position and immediately continue
- MOVE command:
  - Attempts one step along current path per tick
  - If target reached, enters TARGET state
  - If path blocked, enters BLOCKED state and continues to next command
  - Robot does not move if already in TARGET state
  - Each tick: same one-step forward (no progress check inside MOVE)
- WAIT command blocks execution for N ticks (costs 1 tick + N ticks = N+1 total)
- GOTO commands execute immediately (no time cost)
- IF commands evaluate condition immediately and jump or continue (no time cost)
- Empty lines (NOP) consume no tick and execute immediately
- Program execution flow: after last command in program, loop returns to first command
- Program continues executing in loop unless END command or ERROR occurs
- IF statement without matching jump condition continues to next command

### Condition Evaluation
Each IF condition evaluates to true/false at execution time:
- **AT TARGET**: Robot position == target position (target must be set)
- **HAVE TARGET**: Robot target is set (target position is not None)
- **LOADING**: Robot is currently in LOADING state (transfer in progress)
- **UNLOADING**: Robot is currently in UNLOADING state (transfer in progress)
- **FULL**: Robot inventory amount == robot capacity
- **EMPTY**: Robot inventory amount == 0

### Label System
- Labels must start with `:` and contain uppercase letters and numbers
- Label names are case-sensitive (`:LOOP` ≠ `:loop`)
- Labels cannot be on same line as command: `:START GOTO :next`
- Undefined labels cause program error (halt execution)
- No forward/backward restriction - can jump anywhere


### Error Handling
- **Label not found**: ERROR(invalid label: LABEL_NAME) - program halts immediately
- **Object ID not found**: ERROR(invalid id: ID) - program halts immediately (SET TARGET #ID)
- **No route to target**: State is set to BLOCKED, program continues (SET TARGET or direction command)
- **Invalid coordinates**: ERROR(invalid coordinates: X Y) - coordinates out of bounds
- **Invalid material amount**: ERROR(invalid amount: N) - N must be positive integer for LOAD/UNLOAD
- **No adjacent object**: Operation fails silently, program continues (LOAD/UNLOAD with no adjacent location)
- **Directional move out of bounds**: Target is clamped to map edge, program continues (UP/DOWN/LEFT/RIGHT)
- **WAIT with invalid parameter**: ERROR(invalid wait time: N) - N must be positive integer

### Robot State During Execution
- Robot status shows: RUNNING (executing line N)
- Can be interrupted with manual commands
- Program state saved in robot.program_text
- Execution pointer saved in robot.program_counter

## Interpreter Implementation Guide

### Parser Requirements
- Case-sensitive parsing (labels and keywords)
- Whitespace is insignificant except for separating tokens
- Comments extend from `;` to end of line
- Label validation: must match pattern `[A-Z0-9]+`, must be unique in program
- Integer validation: all numeric parameters must be valid integers ≥ 0
- Keyword and command matching is case-sensitive (e.g., `MOVE` ≠ `move`)
- Empty lines are valid and treated as NOP (no operation)

### Execution Requirements
- Single command per game tick execution with loop back to start
- Maintain instruction pointer (line number)
- Handle label lookups at parse time, not runtime
- GOTO and IF commands execute immediately (no tick cost)
- All other commands consume exactly 1 game tick
- LOAD/UNLOAD continue progress in background on each tick while active

### State Management
- Track robot position (X, Y)
- Track robot target position (X, Y) or None
- Track robot inventory (current amount, max capacity - defined externally)
- Track robot state (IDLE, MOVING, BLOCKED, LOADING, UNLOADING, TARGET)
- Track program counter (line number, starts at 0)
- Track if LOAD/UNLOAD operation is active (boolean) and current progress (units transferred)
- Pathfinding system (external to interpreter): given target position, return next step on path

### Command Execution Order
1. Parse program into tokens/instructions (pre-execution)
2. Validate all labels exist and are unique
3. Each game tick:
   - Fetch instruction at program counter
   - Parse and execute command:
     - If GOTO: jump to specified label immediately (0 ticks)
     - If IF [NOT] condition: evaluate condition, jump to label if true (0 ticks), continue if false
     - If WAIT: start waiting timer, increment program counter, return (counts as 1 tick start)
     - If other commands (SET TARGET, MOVE, LOAD, UNLOAD, PRINT, ERROR): execute fully (1 tick consumed), increment program counter
   - Check if WAIT timer is active and decrement if so
   - If LOAD/UNLOAD in progress: transfer 1 material unit this tick, check if transfer complete
   - If program counter >= program length: reset to 0 (loop to start)
   - Return to game loop for next tick

## Syntax Grammar (EBNF-style)

```
program          ::= (line)*
line             ::= (label? command) | comment | empty_line
label            ::= ':' IDENTIFIER
command          ::= set_target | move | direction | load | unload | 
                     goto | if_command | wait | end | error | print
comment          ::= ';' TEXT
empty_line       ::= ''  (empty line = NOP)

set_target       ::= 'SET' 'TARGET' (NUMBER NUMBER | '#' NUMBER)
move             ::= 'MOVE'
direction        ::= ('UP' | 'DOWN' | 'LEFT' | 'RIGHT') (NUMBER)?
load             ::= 'LOAD' (NUMBER)?
unload           ::= 'UNLOAD' (NUMBER)?

goto             ::= 'GOTO' ':' IDENTIFIER
if_command       ::= 'IF' (NOT)? condition 'GOTO' ':' IDENTIFIER
condition        ::= 'AT TARGET' | 'HAVE TARGET' | 'LOADING' | 'UNLOADING' | 
                     'FULL' | 'EMPTY'
wait             ::= 'WAIT' NUMBER
end              ::= 'END'
error            ::= 'ERROR' '(' TEXT ')'
print            ::= 'PRINT' '(' TEXT ')'

IDENTIFIER       ::= [A-Z0-9]+
NUMBER           ::= [0-9]+
TEXT             ::= [^)]*
NOT              ::= 'NOT'
```
